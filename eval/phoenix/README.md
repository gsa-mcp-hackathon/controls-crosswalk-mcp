# Phoenix evaluation harness

Runs a LangChain agent against this MCP server over stdio, asks it the gold questions, and scores every answer with two LLM judges. Traces of each tool call go to [Arize Phoenix](https://docs.arize.com/phoenix), where you can see why a question failed. Built from the template's `mcp-eval` skill.

```
eval/phoenix/
├── agent.py            CrosswalkAgent: chat model + MCP tools + Phoenix tracing
├── model_env.py        the model settings shared by the agent and the judges
├── mcp_tools.py        launches the server over stdio and wraps its tools for LangChain
├── judges/             correctness (against the gold answer) and scope judges
├── prompts/            system_prompt_v1.txt (conventions), v2 (adds scope and injection rules),
│                       baseline_prompt.txt (no tools)
├── datasets/crosswalk-eval-0/
│   ├── evaluation.xml  the 15 gold questions, source of truth
│   └── examples/crosswalk-eval-0.csv   generated by build_dataset.py
├── datasets.yaml       dataset registry
├── build_dataset.py    evaluation.xml to CSV
├── create_dataset.py   upload a CSV to Phoenix
└── run_experiment.py   run agent + judges against a Phoenix dataset
```

One difference from the skill: the MCP bridge is `mcp_tools.py` on the FastMCP client, not `langchain-mcp-adapters`, because that package pins the `mcp` library below 2.0 and FastMCP 4 needs 2.x.

## Setup

```bash
uv sync --group dev --group eval
cp .env.example .env     # then fill in the evaluation section
```

The `.env` picks one model provider with `MODEL_PROVIDER` and always needs the two model ids, `AGENT_MODEL` and `JUDGE_MODEL`. `PHOENIX_COLLECTOR_ENDPOINT` is optional.

| `MODEL_PROVIDER` | Settings it needs |
|---|---|
| `openai`, the default | `OPENAI_API_KEY`. Set `OPENAI_BASE_URL` only for an OpenAI-compatible endpoint other than OpenAI itself. |
| `watsonx` | `WATSONX_URL`, `WATSONX_API_KEY`, and `WATSONX_PROJECT_ID`. See the [IBM credentials guide](https://dataplatform.cloud.ibm.com/docs/content/wsj/analyze-data/fm-credentials.html). |

On watsonx.ai the agent model must support tool calling. This lists the models a region serves that do, and it needs no key. Keep the single quotes, because zsh treats `!` inside double quotes as a history command.

```bash
curl -s 'https://us-south.ml.cloud.ibm.com/ml/v1/foundation_model_specs?version=2024-10-10&filters=task_function_calling,!lifecycle_withdrawn:and&limit=100' \
  | python3 -c "import json,sys; [print(r['model_id']) for r in json.load(sys.stdin)['resources']]"
```

Keep the judge model different from the agent model. The server itself reads none of these, and the harness does not pass any key to it.

The agent and the judges run at temperature 0. OpenAI's reasoning models only accept their default temperature, so the setting is left out for them. See `model_env.py`.

The server must be built first (`data/crosswalk.sqlite`); see the root README.

## Run

```bash
# 1. Start Phoenix in its own terminal. UI at http://localhost:6006.
uv run arize-phoenix serve

# 2. Upload the dataset once.
uv run eval/phoenix/create_dataset.py --dataset-name crosswalk-eval-0

# 3. Run an experiment, with the scoped prompt (v2) or the plain one (v1).
uv run eval/phoenix/run_experiment.py --dataset-name crosswalk-eval-0
uv run eval/phoenix/run_experiment.py --dataset-name crosswalk-eval-0 --system-prompt-version v1

# 4. Run the baseline: the same model with no tools.
uv run eval/phoenix/run_experiment.py --dataset-name crosswalk-eval-0 --no-tools

# 5. Ask every question five times to see how consistent the answers are.
uv run eval/phoenix/run_experiment.py --dataset-name crosswalk-eval-0 --repetitions 5
```

The baseline uses `prompts/baseline_prompt.txt`, which keeps the scope rules but tells the model it has no tools. The difference between the baseline and the v2 run is what the server adds. Each question is allowed 600 seconds; change that with `--task-timeout`.

Read the results in the Phoenix UI under the dataset's experiments. Each row has the agent's answer, the two judge labels with explanations, and a trace of every tool call.

## Try one question without Phoenix

```bash
uv run eval/phoenix/agent.py "Which KSI lists no related SP 800-53 controls?"
uv run eval/phoenix/agent.py --no-tools "Which KSI lists no related SP 800-53 controls?"
```

This still needs the key and the agent model but skips tracing.

## Checks that need no model

- `uv run eval/phoenix/create_dataset.py --dataset-name crosswalk-eval-0 --dry-run` validates the CSV.
- `uv run eval/gold_check.py` re-derives every gold answer through the tools and compares.
- `uv run pytest tests/test_eval_gold.py` does both. When the eval group is installed it also launches the server over stdio through `mcp_tools.py` and runs the agent loop with a scripted stand-in model.

## Reading failures

When a question fails, decide where the fix belongs before changing anything:

- The agent picked the wrong tool or argument: improve that tool's description or parameter text.
- The agent stopped paging or counted early: the system prompt's paging rule, or the tool's `has_more` wording.
- The judge marked a right answer wrong: loosen the correctness template.
- The question itself is ambiguous: fix `evaluation.xml`, rerun `build_dataset.py`, and re-upload.
