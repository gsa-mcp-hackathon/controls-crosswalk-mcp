# Phoenix evaluation harness

Runs a LangChain agent against this MCP server over stdio, asks it the gold questions, and scores every answer with two LLM judges. Traces of each tool call go to [Arize Phoenix](https://docs.arize.com/phoenix), where you can see why a question failed. Built from the template's `mcp-eval` skill.

```
eval/phoenix/
├── agent.py            CrosswalkAgent: gateway model + MCP tools + Phoenix tracing
├── mcp_tools.py        launches the server over stdio and wraps its tools for LangChain
├── judges/             correctness (against the gold answer) and scope judges
├── prompts/            system_prompt_v1.txt (conventions), v2 (adds scope rules)
├── datasets/crosswalk-eval-0/
│   ├── evaluation.xml  the 12 gold questions, source of truth
│   └── examples/crosswalk-eval-0.csv   generated by build_dataset.py
├── datasets.yaml       dataset registry
├── build_dataset.py    evaluation.xml to CSV
├── create_dataset.py   upload a CSV to Phoenix
└── run_experiment.py   run agent + judges against a Phoenix dataset
```

One difference from the skill: the MCP bridge is `mcp_tools.py` on the FastMCP client, not `langchain-mcp-adapters`, because that package pins the `mcp` library below 2.0 and FastMCP 4 needs 2.x.

## Setup

```bash
uv sync --group dev --group eval
cp .env.example .env     # then fill in the evaluation section
```

The `.env` needs the gateway (`USAI_BASE_URL`, `USAI_API_KEY`), the model ids (`AGENT_MODEL`, `JUDGE_MODEL`), and optionally `PHOENIX_COLLECTOR_ENDPOINT`. Keep the judge model different from the agent model. The server itself reads none of these.

The server must be built first (`data/crosswalk.sqlite`); see the root README.

## Run

```bash
# 1. Start Phoenix in its own terminal. UI at http://localhost:6006.
uv run arize-phoenix serve

# 2. Upload the dataset once.
uv run eval/phoenix/create_dataset.py --dataset-name crosswalk-eval-0

# 3. Run an experiment, with the scoped prompt (v2) or the plain one (v1).
uv run eval/phoenix/run_experiment.py --dataset-name crosswalk-eval-0
uv run eval/phoenix/run_experiment.py --dataset-name crosswalk-eval-0 --system-prompt-version v1
```

Read the results in the Phoenix UI under the dataset's experiments. Each row has the agent's answer, the two judge labels with explanations, and a trace of every tool call.

## Try one question without Phoenix

```bash
uv run eval/phoenix/agent.py "Which KSI lists no related SP 800-53 controls?"
```

This still needs the gateway variables but skips tracing.

## Checks that need no model

- `uv run eval/phoenix/create_dataset.py --dataset-name crosswalk-eval-0 --dry-run` validates the CSV.
- `uv run eval/gold_check.py` re-derives every gold answer through the tools and compares.
- `uv run pytest tests/test_eval_gold.py` does both, and also launches the server over stdio through `mcp_tools.py` when the eval group is installed.

## Reading failures

When a question fails, decide where the fix belongs before changing anything:

- The agent picked the wrong tool or argument: improve that tool's description or parameter text.
- The agent stopped paging or counted early: the system prompt's paging rule, or the tool's `has_more` wording.
- The judge marked a right answer wrong: loosen the correctness template.
- The question itself is ambiguous: fix `evaluation.xml`, rerun `build_dataset.py`, and re-upload.
